# 医院门诊管理系统需求分析（XMind 大纲导出）
- 医院门诊管理系统（对标小型 HIS 门诊业务）
  - 系统概述
    - 建设目标：模拟医院门诊业务 Web 后台，覆盖挂号、就诊、处方、收费全流程
    - 对标对象：小型 HIS 门诊子系统
    - 使用者角色
      - 管理员 ADMIN：系统管理、全部业务权限
      - 医生 DOCTOR：查看挂号、开具处方、管理患者
      - 挂号员 REGISTRAR：患者建档、挂号、退号
      - 收费员 CASHIER：处方收费、退费、报表
  - 功能性需求
    - 患者档案管理：建档、查询、修改、删除（唯一约束：病历号/身份证/电话）
    - 挂号管理：选择排班挂号、自动收挂号费、排队号、退号恢复号源
    - 医生排班：按医生/日期/班次排班、号源管理、停诊保护（有挂号不可停诊）
    - 处方开具：多药品明细、库存校验、金额自动计算、状态机（待收费→已收费→已退费/已作废）
    - 收费退费：处方收费扣库存、退费恢复库存、退号联动退挂号费
    - 药品目录：药品信息、价格、库存、启用/停用
    - 报表查询：今日挂号统计、收费日报、处方明细、医生工作量
    - 登录与权限：角色权限控制、操作日志
  - 数据库设计（MySQL）
    - 12 张核心表
      - 基础：roles / users / departments / doctors
      - 业务：doctor_schedules / patients / registrations
      - 处方：medicines / prescriptions / prescription_items
      - 财务与日志：payments / operation_logs
    - 5 个视图：今日挂号、排班、处方明细、收费日报、医生工作量
    - 7 个存储过程：新增用户/医生、挂号、退号、开方、收费、退费（全部事务）
    - 4 个触发器：挂号/收费/建档自动写日志、排班停诊保护
    - 索引：挂号、排班、处方、收费、日志高频查询字段
  - 核心业务流程
    - 就诊主流程：患者建档 → 排班 → 挂号（收挂号费）→ 医生开方 → 收费（扣库存）→ 取药
    - 退费流程：已收费处方 → 收费员退费 → 恢复库存 → 处方已退费
    - 退号流程：待就诊挂号 → 退号 → 恢复号源 → 退回挂号费
    - 状态机
      - 挂号：待就诊 → 就诊中 → 已就诊 / 已退号
      - 处方：待收费 → 已收费 → 已退费 / 已作废
      - 收费：已收费 → 已退费
  - 技术栈与工具
    - 后端：Python 3.14 + Flask 3.1 + mysql-connector-python
    - 数据库：MySQL 8.4（数据库 hospital_outpatient）
    - 前端：Jinja2 模板 + CSS（HIS Web 管理端）
    - 项目管理：禅道（需求、任务、测试用例、缺陷）
    - 测试方法：黑盒测试（功能测试用例 50 条）
    - 设计工具：XMind（本图）
  - 测试方案（黑盒测试）
    - 测试范围：登录权限、患者、挂号、排班、处方、收费退费、报表导出、数据一致性
    - 方法：等价类划分、边界值分析、错误推测法
    - 测试用例：docs/黑盒测试用例_医院门诊管理系统.xlsx（50 条，禅道导入格式）
    - 自动化冒烟：verify_hospital.py（登录→挂号→开方→收费→退费→退号回归）
    - 关键校验点：号源守恒、库存守恒、状态机流转、触发器日志、事务回滚
